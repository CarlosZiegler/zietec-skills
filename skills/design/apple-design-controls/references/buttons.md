# Buttons

- Use a button for an immediate action and make the outcome clear through text or an established symbol.
- Use the appropriate role for primary, cancel, and destructive actions. A destructive choice should not become the primary default merely because it is likely.
- Distinguish the preferred action through style rather than arbitrary size differences.
- Provide a visible pressed state and truthful feedback if completion takes time.
- Give custom controls the full interaction and accessibility behavior of a button.

Inspect platform guidance before choosing shapes or widths. For example, full-width primary buttons are useful on Apple Watch, while current iOS layout guidance takes a different approach.

Source: [Apple HIG — Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons). Checked 2026-09-08.
