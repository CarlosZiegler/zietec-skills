# Dark Mode

- Respect the system appearance preference and generally avoid adding a redundant app-specific appearance setting.
- Design both appearances deliberately. Use adaptive backgrounds and semantic label colors instead of simply inverting a light palette.
- Check content, artwork, icons, and controls against the actual background and material. Provide separate assets when one version cannot remain clear.
- Use system text-entry surfaces and background roles to preserve appropriate contrast and elevation behavior.
- Consider a permanently dark interface only when the experience itself gives a strong reason, such as a specialized immersive context.

Inspect mixed content, bright images, disabled controls, and elevated surfaces. A readable main screen does not prove that sheets, fields, and custom graphics work in both appearances.

Source: [Apple HIG — Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode). Checked 2026-09-08.
